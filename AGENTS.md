# Portfolio Project Instructions

## Project Overview

- This is a personal, single-page developer portfolio built with Astro.
- Preserve the existing architecture, components, design system, and section structure.
- The portfolio is designed around a cinematic, editorial visual identity.

## Design Guidelines

- Dark theme colors:
  - Background: #101114
  - Surface: #24262C
  - Text: #F3F1ED
  - Accent: #D88A46
- Preserve the existing light theme (Warm Paper).
- Keep the design responsive across desktop, laptop, tablet, and mobile.
- Avoid unnecessarily heavy effects. The development machine is a Lenovo ThinkPad T470.
- Prefer lightweight CSS, SVG, and TypeScript solutions.

## Portfolio Structure

The portfolio is one scrolling page containing:

1. Home
2. About
3. Education
4. Projects
5. Tech Stack
6. Experience
7. Contact

Do not turn these sections into separate pages.

## Mr. Fresh

- Mr. Fresh is the portfolio's 2D orange tabby mascot.
- Preserve the existing mascot assets, controller, interactions, and animations.
- Treat the original mascot resource files as read-only.
- Do not replace the mascot with a 3D model or introduce WebGL/Three.js.
- Do not rewrite the mascot system unless explicitly requested.

## Existing Features

- Preserve the interactive Philippines education map.
- Preserve the Project Orbit interface and project navigation.
- Preserve the interactive Tech Stack layout.
- Preserve the Experience section and its Cebu map.
- Preserve existing theme switching and animation controls.
- Parallax has been removed. Do not reintroduce it.

## Development Rules

- Inspect the existing implementation before making changes.
- Follow the project's established coding conventions.
- Make only changes related to the requested task.
- Do not unnecessarily replace working components.
- Do not delete assets, dependencies, or existing features without permission.
- Do not deploy, publish, or push changes without approval.
- Ask before making major architectural changes.

## Testing

- Inspect package.json to identify the available scripts.
- Run relevant tests and the production build after implementation.
- Check both dark and light themes.
- Check responsive layouts and existing interactions.
- Report any failed tests instead of claiming they passed.

## Working Style

- Understand the existing code before editing.
- Explain the implementation plan before major changes.
- Work incrementally and keep changes focused.
- Summarize modified files and verification results when finished.
- Stop and ask if an instruction conflicts with existing functionality.
